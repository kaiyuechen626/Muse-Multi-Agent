# QQ 私聊接入（开发版）

在电脑端“设置 → QQ 私聊接入”配置。AI 使用一个你提供的普通 QQ 账号，你用另一个 QQ 账号与它互为好友。选择已有 Muse 角色即可复用人格与记忆。支持好友文字与图片私聊、来信自动回复，以及按间隔主动聊天；不接入群聊或语音。

也可以从 **角色库 → 右键角色 → 编辑角色 → 绑定 QQ 号** 操作：填写给 AI 使用的 QQ 号及你接收消息的 QQ 号，点击“绑定并开启自动回复”。此入口沿用本机连接地址与凭据，核对桥接实际登录账号和好友后立即生效。首次配置桥接可点击“QQ 连接设置”。绑定信息只存在本机连接配置中，不随角色卡导出或手机同步。

当前一个本地桥接由一个角色使用。切换到其他角色时须明确勾选切换；切换后主动聊天默认关闭，需另行开启。保留现有同角色绑定不会重建 QQ 聊天；解除绑定会暂停收发，但保留历史聊天和记忆。角色人设仍通过角色表单的保存按钮保存，QQ 绑定按钮独立即时保存。

## 准备与配置

1. 按 [NapCat 官方文档](https://doc.napneko.icu/)自行安装本地桥接并登录给 AI 使用的 QQ 号。本项目不包含 NapCat；普通 QQ 客户端登录本身不能提供消息接口，第三方桥接的兼容性和账号风控取决于 QQ 与桥接项目。
2. 在 NapCat 开启 OneBot 11 HTTP 服务端，监听 `127.0.0.1`，例如端口 `3000`，设置 Access Token。在 Muse 填入地址与相同 Token。
3. 在 Muse 填入 AI QQ 号、你的 QQ 号和 Muse 角色，保存后点击“测试连接”。测试仅调用 `get_login_info` 核对账号，不发送消息。
4. 展开 Muse 的“配置 NapCat 消息上报”，复制 URL（默认 `http://127.0.0.1:3210/api/qq/events`）与签名密钥。在 NapCat 新增 HTTP 客户端事件上报，将消息格式设为 `array`，配置 URL，并将签名密钥填入该客户端的 **Token** 字段（不是服务端的 Access Token）。NapCat v4.18.41 使用此 Token 计算 `X-Signature: sha1=...`（原始请求体的 HMAC-SHA1）。其他兼容实现可能称此字段为 Secret。上报端须支持签名；Muse 拒绝无签名事件。
5. 开启“QQ 自动回复”，先从你的 QQ 发送一条文字测试。首次收到消息后建立专用“QQ · 角色名”聊天。电脑、Muse 服务、NapCat 和模型连接均需在线。

## 记忆与同步

QQ 来信使用同一角色的记忆检索、上下文摘要和自动记忆提取。成功回复后按角色自动记忆开关处理；主动生成的开场白不作为新用户事实提取。聊天与角色记忆保存于原有 Muse 数据结构，可用已有局域网同步传到兼容手机端。QQ 聊天不自动合并进其他 Muse 聊天的上下文，但共享角色的长期记忆。

只由电脑桥接发送 QQ 消息。手机离线时，电脑可继续收发，重连后同步。连接配置、QQ 号码、签名 Secret、Token、事件队列与发送确认记录留在本机 `data/qq-channel.json`，不进入手机同步或完整备份。该文件包含凭据，请按私人数据保护；换电脑需重新配置。聊天本身可能包含你发来的个人信息，会和正常聊天一样同步、备份并发送给模型。

## 图片交互

收到纯图片或图文混发消息后，Muse 从本机桥接获取图片，使用 `deepseek-flash` 识别，再让原角色结合图片内容、文字和既有记忆回复。沿用已有 DeepSeek 密钥；图片会发送到 DeepSeek，产生模型用量。图片中的文字和模型识别结果不作为用户本人陈述提取长期记忆，用户随图输入的文字仍按原规则处理。识图失败时保留收到的图片，并提示角色不能声称已看清。离线补回也支持尚未回复的图片，前提是 QQ 仍能下载它。

在“QQ 私聊接入 → 角色图片库”选择上方角色，上传图片并填写说明（例如“开心挥手，适合打招呼”）。角色可按上下文发送该角色图库中的图片，也可以发回当前 QQ 聊天最近 20 条消息里的图片。发图目标仍固定为已绑定的收件好友；一次图文回复通过一个 QQ 消息提交，共用原有发送回执与不确定结果不重发机制。当前实现发送已有图片，不生成新图片、不从网页搜索图片，不接受模型指定任意文件路径或网址。

单图最多 2 MB，支持 PNG/JPEG/WebP/GIF，一条消息最多 4 张，每角色图库最多 20 张。原图和识别结果保存在 Muse 聊天中，可随聊天 JSON 导出、完整备份及兼容客户端同步。图片不经远程 URL 展示；备份清洗验证真实图片类型。图库模板保存在本机 `data/qq-images.json`，不随角色卡导出或手机同步；已经发出的图片保存在聊天内。现有同步仍限制单份聊天资料 8 MB，完整备份仍限制 63 MB，图片较多的聊天可能超过这些限制。旧版手机未必能展示新增图片字段，尚未进行手机真机图片验证。

本机部署已在 NapCat OneBot 配置中开启 `enableLocalFile2Url`，使 `get_image` 返回 Base64。其他部署也应开启此项并重载桥接。无法返回 Base64 时仅尝试受限的 QQ 官方图片 CDN HTTPS URL；不读取上报事件中的本地路径，不下载任意网址。历史图片缓存或链接失效时请重新发送。

## QQ 空间动态

支持通过当前绑定的 AI QQ 账号发布纯文字或图文说说。QQ 中单独发“发动态：主题或正文”（也支持“帮我发条空间动态……”），角色生成正文、配图与可见范围的预览，默认好友可见。核对后回复“发布动态 六位确认码”，或“取消动态 六位确认码”。确认码绑定当前角色、AI QQ 和收件 QQ，15 分钟有效。可在主题中明确要求“仅自己可见”或“所有人可见”；配图仅从当前角色图库或当前 QQ 聊天最近的图片中选取，最多 4 张。若要保留精确正文，可在 Muse 手工填写后预览。

Muse 的“设置 → QQ 私聊接入 → QQ 空间动态”可填写精确正文、选择图片和可见范围、生成预览、确认发布及查看记录。预览保存后才出现对应的发布按钮，发布使用保存的正文与图片，不会在确认后重新改写。当前不自动定时发布，不执行图片中的发布指令。模型只生成草稿，不能自行调用发布接口。

发布使用本机 NapCat 的 `send_qzone_msg` 接口，显式传入可见范围：好友 4、仅自己 64、所有人 1。每次发布前核对真实 QQ 登录账号，先保存尝试状态；收到有效 `tid` 才标记已发布。重启发现发布中断或接口失败无法判断结果时，标记“结果不确定”，不会自动重发，同一确认码也不能再次提交。离线期间收到的发布确认不会在重新上线时自动执行，须本人重新确认。QQ 空间尚未开通、登录过期或平台限制可能导致发布不可用。

草稿与发布记录仅保存在本机 `data/qq-qzone.json`，最多保留最近 20 条，不进入完整备份或局域网同步。QQ 中的预览与发布回执仍按普通聊天保存、同步。此功能不提供删除已发布动态；需要删除时请本人在 QQ 空间处理。

## 主动聊天

主动聊天默认关闭。开启后可设 30–1440 分钟间隔、每日 1–20 次上限、时区和免打扰小时，默认北京时间 23:00–08:00 不主动发送。收到你的消息后重算间隔；普通回复不受免打扰限制。“主动聊一句”会实际发送，遵守开关、每日限额与免打扰。开启后通过模型结合当前 QQ 对话及角色记忆生成话题，每次可能发生模型费用；这是按间隔生成话题，尚无独立的事件或心情决策系统。

## 开机后的离线留言补回

“上线后自动补回离线期间的文字和图片消息”默认开启。Muse 和 QQ 桥接恢复后，会读取固定收件好友的私聊历史，补入启用此功能以后、尚未回复过的留言。连续留言按时间顺序保存到 Muse，并尽量合并成一轮回复（每批最多 50 条、合计 30000 字或 4 张图片）。消息保留原发送时间；补回对话同样使用角色记忆、自动摘要和记忆提取。

此功能不要求先开启“允许角色主动给我发消息”，也不消耗主动聊天每日限额。它属于收到留言后的补答，按普通回复处理免打扰。重启后先检查遗留消息，再恢复按间隔主动聊天。设置页显示最近检查结果，并提供“立即检查离线消息”。

恢复使用 NapCat 的 `get_friend_msg_history` 接口，按消息 ID 持久化去重，并检查该账号是否已发出回复。历史分页失败、超出单次 2000 条检查范围时显示错误，不静默跳过。重连后前三分钟保留重叠检查范围，以等待 QQ 同步历史。首次启用或换绑角色/账号以当时为起点，不自动补答更早的旧聊天。只有 QQ 能同步出来的文字记录才能恢复；撤回、过期、被清理或尚未同步的记录可能不可用。

队列在调用模型前保存。重启时，确认尚未尝试发送的任务可继续，并复用已有消息 ID 和已生成的回复；已获发送回执的任务不重发。发送途中断电而无法确认是否送达的任务保留待核对状态，不冒险自动重发。

本机工作区的 `resume-muse-qq.ps1` 用于 Windows 登录桌面后后台启动 Muse 和已配置的 QQ 桥接，等待网络及登录就绪；当前用户启动目录中的 `Muse QQ Resume.lnk` 调用该脚本。双击桌面 Muse 快捷方式也会自动唤起此后台助手，无需另开桥接。其他账号的普通 QQ 可以保留；仅当助手启动的桥接明确报告绑定的 AI 账号已登录，且启动前只有一个普通 QQ 主进程时，才自动将该客户端切换为桥接。无法确定账号归属时不关闭客户端。该项本机部署配置不随源码分发，也不等于 Windows 登录前启动。QQ 要求扫码/验证码或登录失效时，仍需本人完成验证，Muse 会在桥接恢复后继续检查留言。停用自动回复后，启动助手不会自动登录 QQ。

角色编辑中的绑定状态会另外显示桥接在线、离线或账号不匹配。绑定已保存、自动回复开关已开启，不代表当前已经连接 QQ。

## 故障与边界

- 只接受配置账号发来的好友文字与图片事件，校验桥接登录账号；其他好友和群消息忽略。发送目标固定为配置的你的 QQ 号。
- 接收事件先写入本地队列，按消息 ID 去重，串行处理。最多保留 5000 个已收事件 ID。离线补回开启时接受启用起点之后的旧消息；关闭时，实时上报只接受一天内的事件。
- 每次发送前先保存 Muse 聊天，再记录发送尝试。网络中断可能造成 QQ 已收到但 Muse 无法确认；此时显示“发送结果不确定”，不自动重发，请在 QQ 核对。
- 处理中重启的任务按发送记录恢复：确认未尝试发送的任务继续，已发送的任务结束，结果不确定的任务标记中断供核对。登录不可用时保留队列等待；模型失败不立即循环重试，确认未尝试发送的任务可在下次启动继续。
- 更换两个 QQ 号或角色会取消待处理队列并建立新绑定。停用不删除聊天。绑定聊天删除后会停止处理；可切换角色保存后再重新绑定原角色以新建聊天。
- Muse 聊天保存不等于 QQ 送达，发送状态以 QQ 接入设置为准；手机同步的是聊天内容，不含发送确认。兼容客户端可保留图片字段；旧版手机的图片展示能力需要另外验证。
