# 每个 AI 的记忆目录

默认位置是应用上一级的 `memory` 文件夹。例如应用目录为 `Muse-Multi-Agent/` 时，默认写入同级的 `memory/`。也可通过 `MUSE_MEMORY_DIR` 配置。每个 AI 使用“名称--完整身份 ID”目录，避免同名角色串记忆；角色改名后保留目录位置，里面的名称自动更新。

每个 AI 都有：

- `对话记录/`：完整聊天 JSON，以及方便阅读的 Markdown，保留消息 ID、时间、聊天分支和原有记录。检索命中后从这里重新读取原文和邻近消息。
- `每日备份/`：按北京时间归集当天全部聊天的 JSON，及包含 AI 整理、聊天链接、原文摘录和当日新增长期记忆的 Markdown。
- `向量索引/`：本角色的持久化稀疏 TF-IDF 向量和原文位置，余弦相似度排序。联网聊天时模型会扩展同义表达；超时自动使用本地查询。这不是神经网络 embedding，不能保证任何改写都能召回。
- `长期记忆.md`：已有长期记忆，自动提取或在 Muse 中增删改后同步；`长期记忆.json` 保存结构化记录及删除标记。
- `人格.md`：人格、系统设定、场景、示例、开场白和补充指令；`人格.json` 保留完整角色信息。
- `记忆一览.md`：记忆统计、每日整理目录以及每份聊天的链接。

新建角色、导入角色、手机同步和完整备份恢复会自动建立同样的目录。网页和 QQ 聊天都会先检索本角色历史，再读取原文作为本轮背景；回复菜单的“查看本次记忆”可以核对实际带入的原文及来源。角色记忆窗口的“检索历史记忆”可以手动按关键词查找。

应用原有 `data` 数据库继续保存，保证手机同步、回收站和备份恢复兼容。这里是实时同步的记忆资料库，修改人格和长期记忆请使用 Muse 界面；直接改自动生成的 Markdown 会被下次同步覆盖。保存聊天后会更新此目录。若同步失败，应用保留原始数据并补同步，状态可见 `/api/memory-library`。

每日原文备份实时更新。服务运行时每分钟检查已结束的日期，使用已保存的模型连接分块整理；没有连接或请求失败时保留原文与摘录，恢复后自动重试。电脑关机时不运行，下一次启动会补整理。今天的记录会先归档，到北京时间次日再生成 AI 总结。首次迁移的历史日期也会补整理。自动总结不是长期事实，不会未经原文依据写入长期记忆。

聊天和角色在回收站中、彻底删除或改归属后不再用于检索，历史备份副本仍保留。过期和已删除长期记忆不供回答。旧手机备份里当前库缺失的消息仅作为“旧备份补档”保存，不自动恢复或加入回答依据，以免复活曾删除的内容。迁移报告记录校验数量。

迁移工具：在应用目录运行 `node scripts/migrate-memory-library.mjs`。它不修改原始数据库，可重复执行，不创建重复聊天档案。它仅识别本地已导入手机备份中身份映射明确的记录；无法映射会列入报告，不按相似名字猜测归属。

目录内含私人聊天，应按个人数据保管；发布应用源码时不包括此目录。模型会接收本轮选中的历史原文，记忆改写和每日整理会额外使用已配置模型。
